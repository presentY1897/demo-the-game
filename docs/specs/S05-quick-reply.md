# S05. CareTalk 퀵 리플라이

- **갈래**: UX · **의존**: S01, S02 · **판정**: 대기

## 배경 (진단 근거)

CareTalk의 사용자는 **아픈 상태로 낯선 병원에 온 외국인 환자**다. 지금은 자유 텍스트
입력만 있어 타이핑 부담이 크고, 목 서버 번역이 사전 기반(`translate.ts`)이라 사전에
없는 문장은 `[demo]` 폴백으로 떨어져 데모 품질도 나쁘다. 자주 쓰는 문구를 탭으로
보내게 하면 UX와 번역 품질이 동시에 해결된다.

## 명세

### 문구 데이터

- 역할·언어별 자주 쓰는 문구 세트를 `packages/i18n` 리소스에 추가:
  - 환자: 증상 호소("열이 나요", "여기가 아파요"), 요청("천천히 말해 주세요"), 확인 응답.
  - 의료진: 문진("언제부터 아프셨나요?"), 안내("접수 도와드릴게요"), 마무리.
- **mock-server의 번역 사전(`translate.ts`)과 문구를 일치**시켜 퀵 리플라이 전송은 항상
  제대로 된 번역이 붙게 한다. 사전과 리소스의 원천을 한 곳(i18n)으로 모으고 서버가
  import하는 구조로 중복을 없앤다 (계약 단일 원천 원칙과 동일).

### UI

- 입력창 위 가로 스크롤 칩 목록. 상황 그룹(증상/요청/응답)별 구분.
- 탭 → 즉시 전송. **길게 누르면 입력창에 삽입**해 수정 후 전송(문구를 변형하고 싶은 경우).
- 대화가 진행되면 칩 영역은 접을 수 있게(입력창 포커스 시 자동 접힘).
- 터치 타깃·글자 크기는 S06 기준(44pt) 선적용.

## 완성 기준

1. 환자가 타이핑 없이 탭 3회 이내로 "인사 → 증상 전달"까지 도달한다.
2. 퀵 리플라이로 보낸 모든 문구에 `[demo]` 폴백 없이 번역이 붙는다.
3. 길게 누르기 → 편집 → 전송 흐름이 동작한다.
4. 문구 원천이 한 곳(i18n)이고 서버 사전이 그것을 소비한다.

## 테스트

- 유닛(문구 커버리지): i18n 퀵 리플라이 전 문구가 서버 번역 사전에 존재 — `[demo]` 폴백
  0건을 테스트로 보장(원천 단일화 검증).
- 유닛: 칩 탭 → 즉시 send 호출, 길게 누르기 → 입력창 삽입(핸들러 로직 단위).
- 수동: 환자 3탭 시나리오, 칩 영역 접힘/펼침, 편집 후 전송, 언어 전환 시 문구 세트 교체.

## 작업 분해

1. 문구 세트 설계 (ko/en/ja 정도, 역할별 8~12개)
2. i18n 리소스 구조 확장 + mock-server가 공유하도록 재배선
3. 칩 UI + 즉시 전송/길게 눌러 편집
4. 접힘 동작

## 범위 제외

음성 입력(실서비스 영역), 문구 검색, 사용 빈도 기반 정렬, 4개 이상 언어.
