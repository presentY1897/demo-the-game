# S05. CareTalk 퀵 리플라이

- **갈래**: UX · **의존**: S01, S02 · **판정**: 대기

## 배경 (진단 근거)

CareTalk의 사용자는 **아픈 상태로 낯선 병원에 온 외국인 환자**다. 지금은 자유 텍스트
입력만 있어 타이핑 부담이 크고, 목 서버 번역이 사전 기반(`translate.ts`)이라 사전에
없는 문장은 `[demo]` 폴백으로 떨어져 데모 품질도 나쁘다. 자주 쓰는 문구를 탭으로
보내게 하면 UX와 번역 품질이 동시에 해결된다.

## 명세

### 문구 데이터

- 역할·언어별 자주 쓰는 문구 세트를 `packages/i18n` 리소스에 추가:
  - 환자: 증상 호소("열이 나요", "여기가 아파요"), 요청("천천히 말해 주세요"), 확인 응답.
  - 의료진: 문진("언제부터 아프셨나요?"), 안내("접수 도와드릴게요"), 마무리.
- **mock-server의 번역 사전(`translate.ts`)과 문구를 일치**시켜 퀵 리플라이 전송은 항상
  제대로 된 번역이 붙게 한다. 사전과 리소스의 원천을 한 곳(i18n)으로 모으고 서버가
  import하는 구조로 중복을 없앤다 (계약 단일 원천 원칙과 동일).

### UI

- 입력창 위 가로 스크롤 칩 목록. 상황 그룹(증상/요청/응답)별 구분.
- 탭 → 즉시 전송. **길게 누르면 입력창에 삽입**해 수정 후 전송(문구를 변형하고 싶은 경우).
- 대화가 진행되면 칩 영역은 접을 수 있게(입력창 포커스 시 자동 접힘).
- 터치 타깃·글자 크기는 S06 기준(44pt) 선적용.

## 완성 기준

1. 환자가 타이핑 없이 탭 3회 이내로 "인사 → 증상 전달"까지 도달한다.
2. 퀵 리플라이로 보낸 모든 문구에 `[demo]` 폴백 없이 번역이 붙는다.
3. 길게 누르기 → 편집 → 전송 흐름이 동작한다.
4. 문구 원천이 한 곳(i18n)이고 서버 사전이 그것을 소비한다.

## 테스트

- 유닛(문구 커버리지): i18n 퀵 리플라이 전 문구가 서버 번역 사전에 존재 — `[demo]` 폴백
  0건을 테스트로 보장(원천 단일화 검증).
- 유닛: 칩 탭 → 즉시 send 호출, 길게 누르기 → 입력창 삽입(핸들러 로직 단위).
- 수동: 환자 3탭 시나리오, 칩 영역 접힘/펼침, 편집 후 전송, 언어 전환 시 문구 세트 교체.

## 작업 분해

1. 문구 세트 설계 (ko/en/ja 정도, 역할별 8~12개)
2. i18n 리소스 구조 확장 + mock-server가 공유하도록 재배선
3. 칩 UI + 즉시 전송/길게 눌러 편집
4. 접힘 동작

## 범위 제외

음성 입력(실서비스 영역), 문구 검색, 사용 빈도 기반 정렬, 4개 이상 언어.

## 구현 메모 (2026-09-01)

### 문구의 단일 원천

- 카탈로그: `packages/i18n/src/quick-replies.ts`. 문구 하나가
  `{ id, role, group, text: { ko, en, ja } }`이고, 필요하면 사전 매칭 전용 이형
  (`aliases`)과 칩에서 빼는 표시(`dictionaryOnly`)를 단다.
- 소비자 둘이 같은 표를 읽는다.
  - 화면: `quickRepliesFor(role, lang)` → 그룹별 칩 목록 (라벨도 대화 언어로).
  - 서버: `quickReplyTranslationPairs()` → `apps/mock-server/src/translate.ts`가
    (출발 언어, 대상 언어, 정규화 원문) 열쇠로 펼쳐 **1단계 사전**을 만든다.
    3단 폴백 체인(사전 → Azure → `[demo]`, S12)의 구조는 그대로고 데이터 출처만 바뀌었다.
- 하드코딩돼 있던 `enToKo` 표(en→ko 13건)는 사라졌다. 그 문장들은 카탈로그로
  옮기거나(`headache`, `greeting` …) 이형·사전 전용 항목으로 넘겨받아 번역 회귀가 없다.
- **대화 언어 ≠ UI 언어**: 화면 전체는 앱 UI 언어(ko/en 토글)를 따르지만 칩 문구와
  그룹 라벨은 그 사람이 말하는 언어(`myLang`)를 따른다. 그래서 문구는 리소스 트리
  (`resources/{ko,en}.ts`)가 아니라 카탈로그가 언어별로 들고 있고, 칩 영역의 껍데기
  (제목·접기·힌트)만 `quickReply.*` 리소스에 있다.
- 의료진 문구 5개는 `conversation.ts`의 봇 대행 스크립트와 글자 그대로 같게 맞췄다 —
  덤으로 봇이 일본어 환자에게 말할 때도 `[demo]` 없이 번역된다.

### UI

- `screens/caretalk/QuickReplyBar.tsx` — 입력창 위 가로 스크롤, 그룹(구분선 + 라벨)별 칩.
- 탭 → 즉시 전송(초안은 건드리지 않음), 길게 누르기 → 초안 뒤에 이어 붙이고 입력창 포커스.
- 접힘: 입력창 포커스 시 자동으로 접히고, 초안 없이 포커스를 잃으면 다시 펼친다.
  헤더의 토글은 언제나 사용자의 선택이 이긴다. 규칙은 `screens/caretalk/quickReply.ts`의
  순수 함수(`createQuickReplyHandlers` / `nextCollapsed`)로 빼 단위 테스트한다.
- 터치 타깃 44pt, 고정 높이 없음(폰트 스케일 대응) — S06 기준 선적용.
- ko/en/ja 밖의 대화 언어(zh·vi 등)에서는 칩을 아예 내지 않는다 — 번역이 보장되지 않는
  문장을 "자주 쓰는 문구"로 권하지 않기 위해서다. 자유 입력은 그대로 동작한다.

### 테스트

- `apps/mock-server/src/__tests__/quick-reply-dictionary.test.ts` — 카탈로그 전 문구를
  6개 언어 방향으로 돌려 `[demo]`/`[데모 번역]` 0건 + 카탈로그와 같은 번역임을 확인
  (완성 기준 2·4). 열쇠 충돌·사전 적재 누락도 함께 잡는다.
- `apps/live-demo/src/screens/caretalk/__tests__/quickReply.test.ts` — 탭 → send 1회,
  길게 누르기 → 삽입(전송 없음), 접힘 규칙, 언어 전환 시 문구 교체, 인사→증상 2탭.

### 수동 검증 (웹 빌드 + 목 서버)

1. 환자가 **탭 2회**로 인사 → 증상 전달 (기준 1: 3회 이내) ✅
2. 퀵 리플라이로 보낸 문구는 en/ja 모두 마커 없이 번역 ✅
   (`Hello.`→`안녕하세요.`, `熱があります。`→`열이 나요.`, 봇의 ko 문진→일본어)
3. 길게 누르기 → 입력창 삽입(전송 안 됨) → 편집 후 전송 ✅
4. 언어를 ja로 바꾸면 칩 세트가 통째로 교체 ✅ / 포커스 시 접힘·토글로 펼침 ✅

### 남은 것

- 문구 세트는 ko/en/ja 3개 언어(역할별 12개 칩). zh·vi·ru·mn은 관리자 설정(S14)에
  존재하지만 문구가 없어 칩이 뜨지 않는다 — 언어를 늘리려면 카탈로그만 채우면 된다.
- 사용 빈도 기반 정렬·문구 검색·음성 입력은 명세대로 범위 제외.
