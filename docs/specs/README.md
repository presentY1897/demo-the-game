# 명세 (Specs)

두 층위로 관리한다. 마감 기준으로 범위를 자르지 않고 전 작업을 명세화하며,
각 명세의 진행/보류/수정 판단은 리뷰(사용자)가 한다.

- **기능 명세 (F)** — 사용자 집단을 먼저 정의하고 역할별 기능을 설계한다. 제품의 정본.
- **작업 명세 (S)** — F의 기능을 구현 단위로 쪼갠 것. **배경 → 명세 → 완성 기준 →
  테스트 → 작업 분해 → 범위 제외**를 반드시 담는다.

상위 맥락: [중간 점검 문서](../2026-09-01-checkpoint.md)의 §7 진단.

## 규칙

- 명세가 승인되면 해당 작업은 이 문서를 계약으로 삼는다 — 구현 중 명세와 달라지면
  코드가 아니라 명세를 먼저 고친다.
- 모든 S 명세는 **완성 기준**(무엇이 되면 끝인가)과 **테스트**(자동: 유닛/통합 대상,
  수동: 검증 시나리오)를 반드시 포함한다.
- 완료 시 인덱스의 판정을 `완료`로 바꾸고 커밋 해시를 적는다.
