# S13. Symposia 운영 콘솔 — 간사·발표자 기능

- **갈래**: 구조 · **의존**: S01–S03 (라우팅), F01 · **판정**: 대기

## 배경 (F01 근거)

현재 Symposia에는 참가자 기능만 있다. 세션은 서버 부팅 시 자동 재생되고, 간사(세션
생성·코드 발급·시작/종료)와 발표자(발화 제어·자막 모니터)의 자리가 없다 — 학회를
"운영"하는 쪽 여정이 통째로 빠져 있다. F01의 간사·발표자 기능을 하나의 운영 콘솔로
구현한다(데모 판단: 별도 발표자 화면 대신 콘솔에 통합).

## 명세

### 서버 — 세션 라이프사이클 API

- 부팅 시 자동 `broadcaster.start()`를 제거하고 콘솔 제어로 전환:
  - `POST /api/sessions` → 세션 생성 `{ title, speaker, sourceLang, targetLangs }` —
    자막 소스는 데모 스크립트(keynote) 템플릿을 복제.
  - 새 세션의 `id`는 사람이 받아 적을 수 있는 6자리 코드(초대 코드와 같은 문자 집합)로
    발급해 그대로 입장 코드로 쓴다(S02: "세션 코드 = 세션 id").
  - `POST /api/sessions/:id/start | pause | resume | end` — 상태 전이. `end` 시
    `session-ended` 브로드캐스트(프로토콜에 이미 존재). 허용되지 않는 전이는 `409`.
  - `GET /api/sessions/:id/status` → `{ state, viewerCount, position, total, rate }`.
    `total`(스크립트 문장 수)과 `rate`는 콘솔이 진행률과 현재 속도를 새로고침 후에도
    그릴 수 있게 함께 싣는다.
  - 재생 제어: `POST /api/sessions/:id/rate { rate: 0.5–2 }` — 발표자 속도 제어의 데모 대체.
  - 제어 엔드포인트(start·pause·resume·end·rate)는 성공 시 모두 `status`와 같은 본문을
    돌려준다 — 조작 후 재조회가 필요 없다.
  - 스크립트를 끝까지 재생하면 자동으로 `ended`가 되고 `session-ended`를 보낸다
    (기존의 "3초 뒤 처음부터 무한 재시작"은 콘솔 제어와 맞지 않아 제거).
- 기존 `GET /api/sessions`는 `state`와 `viewerCount`를 추가해 유지(참가자 로비·콘솔 공용
  — 콘솔 목록의 시청자 수를 세션마다 status로 다시 묻지 않게 한다).

### 클라이언트 — 콘솔 화면 (`/console`, S03 라우팅)

- **세션 목록**: 상태 배지(대기/재생/일시정지/종료) + 시청자 수.
- **세션 생성 폼**: 제목·발표자·언어 선택(템플릿 기반).
- **세션 상세(운영)**: 입장 코드·QR(S03 URL), 시작/일시정지/재개/종료 버튼,
  재생 속도 컨트롤, **자막 모니터**(참가자와 동일한 스트림을 구독하는 미리보기 —
  기존 자막 컴포넌트 재사용).
- 참가자 화면: `session-ended` 수신 시 "세션이 종료되었습니다" 안내 + 홈 복귀 버튼
  (현재는 이벤트만 있고 화면 처리 없음 — 여기서 마감).
- 인증 없음(데모 한계, F01에 문서화) — 콘솔은 URL로만 진입.

## 완성 기준

1. 콘솔에서 세션을 만들고 시작하면, 참가자가 코드/QR로 입장해 자막을 본다(참가자 자동
   재생 의존 제거).
2. 일시정지/재개/속도 변경이 시청 중인 참가자 화면에 즉시 반영된다.
3. 종료 시 참가자 화면에 종료 안내가 뜬다.
4. 자막 모니터가 참가자와 같은 내용을 보여준다.

## 테스트

- 유닛(서버): 상태 전이 — 허용/불허 전이(대기→재생→일시정지→재생→종료, 종료 후 조작 거부),
  rate 경계값(0.5/2 밖 거부).
- 통합(서버): start 후 SSE 구독 시 자막 흐름, pause 중 이벤트 미발행, end 시
  `session-ended` 수신.
- 유닛(클라): 콘솔 상태 스토어 — status 폴링 반영, 버튼 활성화 조건.
- 수동: 콘솔+참가자 2탭 시나리오(완성 기준 1–4 재현).

## 작업 분해

1. 서버 세션 상태 머신 + API
2. 콘솔 화면(목록/생성/상세)
3. 자막 모니터(기존 컴포넌트 재사용)
4. 참가자 종료 안내 처리
5. 테스트

## 범위 제외

발표자 별도 화면, 실제 STT 입력, 다중 간사 동시 편집, 세션 일정표.

## 구현 메모 — 클라이언트 (2026-09-01)

- **목록 ↔ 상세는 라우트가 아니라 스토어 한 필드로 가른다.** `/console` 아래에 하위 경로를
  늘리려면 `navigation.ts`·`routing/url.ts`·`App.tsx`를 함께 고쳐야 하는데(S03) 그 셋은
  다른 작업과 겹치는 공용 파일이라, 콘솔 안의 화면 전환은 `consoleStore.session` 하나로
  가른다. 대가는 아래 "미완"에 적었다.
- **상태의 정본은 서버, 화면은 거울이다.** 버튼을 눌러도 낙관적으로 상태를 바꾸지 않는다.
  제어 응답이 곧 `status`라 그 값을 그대로 반영하고(재조회 없음), 그 밖의 변화 — 다른 탭의
  조작, 스크립트 끝까지 재생 후 자동 종료, 시청자 수 — 는 2초 폴링으로 들어온다. 자막 SSE에는
  `viewerCount`·`rate`·진행률이 없어(참가자에게 필요 없는 값) 운영 상태를 실어 올 채널이 없다.
- **뒤늦게 도착한 폴링은 버린다.** 제어 요청이 떠 있는 동안(`pending`)의 폴링 응답은 무시한다 —
  "시작"을 누른 직후 그 직전 상태를 담고 출발했던 폴링이 도착해 화면이 되감기는 자리를 없앤다.
- **버튼 활성화 조건은 서버 상태 머신의 거울이다**(`stores/consoleSelectors.ts`). 불가능한
  전이는 눌리기 전에 잠기고, 요청이 떠 있는 동안에는 전부 잠긴다(연타로 409를 만들지 않는다).
  종료된 세션은 속도까지 잠긴다. 잠긴 버튼은 색도 잃는다 — 흐려진 파란 "시작"은 운영석에서
  "지금 누를 수 있는 것"으로 잘못 읽힌다.
- **속도는 슬라이더가 아니라 0.25 스텝의 −/＋** 다. 눌러서 닿는 값이 전부 서버 허용 범위
  (0.5–2) 안이고, 경계에서 버튼이 잠기므로 `invalid-rate`가 날 수 없다. 스텝 계산은
  소수 둘째 자리에서 정리한다(0.25 누적의 부동소수점 찌꺼기 제거).
- **자막 모니터는 참가자와 같은 스트림(`/stream?lang=xx`)을 같은 `CaptionRow`로 그린다.**
  미리보기 전용 경로를 만들지 않아 "모니터엔 나오는데 참가자에겐 안 나온다"가 구조적으로
  불가능하다(완성 기준 4). 재사용을 위해 참가자 화면의 자막 줄을 `components/CaptionRow.tsx`로
  뽑았다(동작 변경 없음). 대가 하나 — 이 구독도 서버의 `viewerCount`에 1로 잡힌다. 숨기지 않고
  상세 화면에 그렇게 적었고, 모니터를 끄는 토글을 뒀다.
- **생성 폼의 언어 목록(ko/en/ja/zh)은 클라이언트 상수다.** 서버가 템플릿 언어를 알려주는
  엔드포인트를 두지 않아서다. 어긋나면 `unsupported-language`가 폼 안에 그대로 뜬다 —
  조용히 실패하지 않는 쪽으로 대신 막았다.
- **실패는 안정 코드로 분기해 문장으로 바꾸고, 모르는 코드는 코드째 보여준다**
  (`screens/console/errors.ts`). 시연 중에 "요청을 처리하지 못했습니다"만 뜨면 원인을 찾을
  실마리가 사라진다.
- **참가자 종료 마감**: `session-ended`를 받으면 자막 위에 안내 카드를 덮고 "홈으로"와
  "자막 다시 보기"를 준다. 다시 보기를 고르면 지나간 자막을 훑을 수 있고 하단에 종료 배너가
  남는다. 문구 키가 `caption.*`가 아니라 `console.ended.*`인 것은 i18n 리소스 파일에서
  네임스페이스별로 작업을 나눠 쓰고 있어서다(종료 마감 자체가 S13 몫).
- **인증은 없다.** 콘솔은 `/console` URL을 아는 사람만 들어온다(F01의 데모 한계).

### 수동 검증 (2026-09-01, 목 서버 + 웹 빌드 2탭)

완성 기준 1–4를 브라우저 2탭으로 재현했다.

1. 콘솔에서 세션 생성 → 코드 발급(`KD9M93`) → 시작 → 다른 탭에서 `/session/kd9m93` 입장 →
   자막 수신 확인.
2. 일시정지 중 참가자 화면이 멈추고(4초 동안 변화 없음) 재개하면 다시 흐른다. 속도는
   0.5배에서 6초간 +119자, 2.0배에서 +414자 — 시청 중인 화면에 그대로 반영된다.
3. 종료 시 참가자 화면에 종료 안내와 홈 복귀 버튼이 뜨고, 누르면 `/`로 돌아간다.
4. 모니터에 참가자와 같은 문장이 같은 시점에 보인다.

버튼 활성화도 실제 DOM에서 확인했다: 대기(시작·종료만), 재생(일시정지·종료), 일시정지
(재개·종료), 종료(전부 잠김), 속도 0.5배에서 −잠김 / 2.0배에서 ＋잠김.

### 미완 — 남겨 둔 것

- **상세 화면에 주소가 없다.** 새로고침하면 콘솔 목록으로 돌아온다. 확장 지점은 `Route`의
  `{ name: 'console' }`에 세션 id를 옵션으로 더하고 `routing/url.ts`에 `/console/:id`를
  넣는 것 하나뿐이다(S03 파일과 함께 손대야 해서 미뤘다).
- **운영 상태는 폴링(2초)이다.** 서버가 운영용 이벤트 채널을 주면 `useSessionStatusPolling`
  한 곳만 갈아끼우면 된다.
- **세션 편집·삭제가 없다**(명세 범위 밖). 종료된 세션도 목록에 계속 쌓인다.
- **홈 화면(`HomeScreen`)에 같은 상태 배지 로직이 인라인으로 남아 있다.** 콘솔은 새로 만든
  `components/SessionStateBadge.tsx`를 쓴다 — 동시 작업 중인 파일이라 홈은 건드리지 않았다.
