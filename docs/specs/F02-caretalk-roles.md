# F02. 기능 명세 — CareTalk (병원 대화 통역)

- **층위**: 기능 명세(F) — 사용자 집단을 먼저 정의하고 역할별 기능을 설계한다.

## 사용자 집단

| 역할 | 정의 | 사용 맥락 | 핵심 목표 |
|---|---|---|---|
| **병원 내 관리자** | 원무·국제진료팀 담당자 | 데스크/사무실, 운영 관점 | 상담이 어디서 몇 건 돌아가는지 파악, 기관 설정 관리 |
| **의사** (설명할 의료진) | 진료·시술 설명을 하는 의사/코디네이터 | 진료실, 반복 업무, 짧은 호흡 | 언어 장벽 없이 빠르고 정확하게 설명 |
| **환자** | 외국인 환자 | 낯선 병원, 불안, 디지털 숙련 다양 | 타이핑 부담 없이 증상을 전하고 설명을 이해 |

## 역할별 기능 설계

| 기능 | 설명 | 데모 구현 | 작업 |

| 지원 언어 설정 | 기관이 제공하는 환자 언어 관리 — 환자 온보딩(S02) 언어 목록이 이를 따름 | ✅ 토글 수준 | S14 |
| 의료진 계정·권한 관리 | | ❌ 실서비스 영역 | — |
| 상담 로그 보존·개인정보 정책, 통계 | | ❌ 실서비스 영역 (문서로 언급만) | — |

## 도메인 흐름 (역할 간 상호작용)

```
관리자: 지원 언어 설정 ·· 현황 대시보드에서 방 모니터
의사:   방 생성 → 코드/QR을 환자에게 → 대화(정형 문구+자유 텍스트) → 상담 종료
환자:   코드/QR 입장 → 언어 선택 → 대화(퀵 리플라이 위주) → 종료 안내
봇:     의사가 아직 없는 방에서만 의료진 역할 대행 (1인 시연용 — 실사용 흐름과 공존)
```

## 데모 범위 원칙

- 관리자 기능은 "읽기 위주 최소"(현황 + 언어 설정)로 구현하고, 계정·권한·로그는 제외를
  명시한다.
- 역할 진입에 인증 없음(데모 한계로 문서화). 의료 데이터인 만큼 실서비스라면 가장 먼저
  필요한 것이 인증·암호화·보존 정책임을 F 문서에 남긴다 — 리뷰어 대상 인지 증빙.
