# S14. CareTalk 관리자 뷰 — 상담 현황·기관 설정

- **갈래**: 구조 · **의존**: S01 (방 라이프사이클), F02 · **판정**: 대기

## 배경 (F02 근거)

병원 내 관리자(원무·국제진료팀) 역할이 설계에 없다. 상담이 몇 건 돌아가는지 볼 수 없고,
환자에게 제공할 언어도 코드에 박혀 있다. F02의 관리자 기능을 "읽기 위주 최소"로 구현한다.

## 명세

### 서버

- `GET /api/admin/rooms` → 열린 방 목록
  `[{ inviteCode, memberCount, roles: ['staff','patient'], lastActivityAt, botActive }]`
  — 대화 내용은 포함하지 않는다(개인정보 인지의 표시, F02 문서화와 일관).
  응답 스키마를 `z.strictObject`로 두어 명세에 없는 필드가 붙으면 파싱이 실패한다.
  `lastActivityAt`은 epoch ms. 참여자가 0명인 방도 S01의 TTL 전까지는 `memberCount: 0`으로
  남는다 — "종료된 상담"으로 표시할지 숨길지는 화면 판단.
- `GET /api/admin/settings` / `PUT /api/admin/settings` → `{ patientLangs: ['en','ja',…],
  supportedLangs: [...] }` (메모리 보관). 응답에 `supportedLangs`(기관이 켤 수 있는 전체
  후보)를 함께 실어 관리자 토글 목록의 소스로 쓴다. 환자 온보딩(S02)의 언어 목록은
  `patientLangs`를 따른다.
  - 서버가 아는 후보는 `en·ja·zh·vi·ru·mn`, 기본값은 `en·ja·zh`.
    목록 밖 코드와 빈 배열은 `400 { error, message }`로 거부한다.

### 클라이언트 — 관리자 화면 (`/admin`, S03 라우팅)

- **상담 현황**: 방 테이블(코드·인원·역할 구성·마지막 활동·봇 대행 여부), 10초 간격
  refetch(TanStack Query) — 실시간 소켓은 과잉이라 폴링으로.
- **지원 언어 설정**: 언어 토글 목록 → PUT 저장 → 저장 확인 피드백.
- 인증 없음(데모 한계, F02에 문서화). 실서비스 최우선 과제가 인증·로그 정책임을 화면
  각주로도 표기(리뷰어 인지 증빙).

## 완성 기준

1. 의사가 방을 만들면(S01) 관리자 화면에 10초 내 나타나고, 종료하면 사라진다.
2. 관리자가 언어를 끄면 환자 온보딩(S02) 목록에서 즉시 빠진다.
3. 관리자 화면 어디에도 대화 내용이 노출되지 않는다.

## 테스트

- 유닛(서버): admin/rooms 직렬화 — 대화 내용 필드 부재 보장, 방 정리(S01 TTL) 후 목록 반영.
- 유닛(서버): settings 검증 — 지원 목록 밖 언어 코드 거부, 빈 배열 거부(최소 1개 언어).
- 유닛(클라): 언어 설정 스토어/쿼리 — PUT 후 온보딩 언어 소스 갱신.
- 수동: 3탭 시나리오(의사 방 생성 → 관리자 현황 확인 → 언어 토글 → 환자 온보딩 반영).

## 작업 분해

1. 서버 admin 엔드포인트 + settings 저장
2. 관리자 화면(현황 테이블 + 언어 설정)
3. S02 언어 목록을 settings 조회로 전환
4. 테스트

## 범위 제외

인증·권한, 상담 로그·통계, 의료진 계정 관리, 다기관(멀티 테넌트).

## 구현 메모 (클라이언트, 2026-09-01)

### 빈 방(`memberCount: 0`) 표시 정책 — 화면 판단

서버는 방을 TTL(24시간) 전까지 지우지 않으므로 "방금 연 방"과 "끝난 상담"이 응답에서
똑같이 `memberCount: 0`으로 온다. 화면은 **`lastActivityAt`과의 간격**으로 둘을 가른다
(`screens/admin/rooms.ts`).

| 상태 | 조건 | 화면 |
|---|---|---|
| 진행 중 | `memberCount > 0` | 기본 목록 |
| 대기 중 | 0명이고 마지막 활동 60초 이내 | 기본 목록 (환자 입장 대기) |
| 종료됨 | 0명이고 마지막 활동 60초 초과 | 접힌 "종료된 상담 N건 보기" |

- **왜 숨기지 않고 접는가**: 관리자의 목표는 "지금 몇 건이 도는가"라 끝난 방은 소음이지만,
  통째로 지우면 데이터가 조용히 사라진다(무음 실패). 개수는 항상 보인다.
- **왜 60초인가**: 폴링 주기(10초)의 6배. 환자가 새로고침하느라 몇 초 비는 방을 종료로
  오판하지 않으면서, 상담이 끝나면 1분 안에 기본 목록에서 빠진다(완성 기준 1의 "사라진다").
- 방을 만들자마자(WS 참여 전) 폴링이 돌면 0명으로 오므로, **"막 만든 방"이 종료로 분류되지
  않게** 하는 것이 이 규칙의 실질적 이유이기도 하다.

### 온보딩 반영 경로 (완성 기준 2)

`ADMIN_SETTINGS_QUERY_KEY`(= `['admin-settings']`)를 `src/api/adminKeys.ts` 하나에 두고
관리자 화면과 `hooks/useLanguageOptions`가 같이 쓴다. 저장 성공 시
`screens/admin/settingsCache.ts`가 ① `setQueryData`(화면 즉시 반영) ② `invalidateQueries`
(온보딩의 `staleTime: 60초`를 무시하고 재조회)를 함께 한다. 이 경로는
`screens/admin/__tests__/settingsCache.test.ts`가 검증한다.

### 그 밖

- 마지막 언어 끄기는 UI에서 먼저 막고(`toggleLanguage` → `last-language`), 그래도 서버가
  거절하면(`unsupported-language`·`invalid-body`) 이유를 인라인 문구로 옮긴다.
- 화면 폭 720px을 기준으로 표(데스크톱)와 카드(폰) 레이아웃을 바꾼다.
- 인증 없음·대화 내용 미노출을 "데모 범위" 각주로 화면 하단에 상시 표기한다.
