# 0007. CareTalk 대화 번역은 사전 → Azure Translator → `[demo]` 3단 폴백 체인으로 처리한다

- **상태**: Accepted
- **날짜**: 2026-09-01
- **관련**: [S12](../specs/S12-translation-api.md), [F02](../specs/F02-caretalk-roles.md),
  [0003](./0003-sse-for-broadcast-ws-for-conversation.md)

## 맥락 (Context)

CareTalk 대화 번역이 사전 매칭 + `[demo]` 마커 폴백뿐이라, 정형 문구(S05) 밖의 자유 텍스트는
번역이 되지 않는다. 실번역 API를 붙이려는데 두 요구가 정면으로 충돌한다.

- **데모는 저장소 클론만으로 돌아가야 한다.** 면접관·리뷰어가 키 발급 없이 바로 실행한다.
- **자유 텍스트도 실번역이 돼야 한다.** 그러려면 외부 API 키가 필요하다.

또 하나, 번역 대상 범위를 정해야 한다. Symposia 자막도 API로 번역할지, 스크립트 내장 번역을
유지할지.

## 결정 (Decision)

- 번역을 **3단 폴백 체인**으로 구성한다: ① 사전 매칭 → ② Azure Translator(키가 있을 때만,
  타임아웃 3s) → ③ `[demo]` 마커 폴백. 키는 **선택 사항**이며, 없으면 ①③만으로 기존과
  동일하게 동작한다.
- 키는 **서버 환경변수로만** 둔다. 클라이언트는 번역 API를 직접 호출하지 않는다.
- **Symposia 자막은 API 대상에서 제외**하고 스크립트 내장 번역을 유지한다. API 대상은
  **CareTalk 대화뿐**이다.
- Azure 성공 결과만 (출발 언어, 대상 언어, 원문) → 번역 **LRU 캐시**(상한 1,000건)에 담는다.
- 호출 실패는 경고 로그 + 폴백이며, 대화 흐름을 막지 않는다.

## 검토한 대안 (Alternatives)

| 대안 | 장점 | 단점 | 탈락 사유 |
|------|------|------|-----------|
| **API 필수 (키 없으면 실행 불가)** | 코드 경로 하나, 동작 예측 단순 | 클론만으로 실행 불가 | 데모의 핵심 조건인 "클론 후 즉시 실행"을 깬다 |
| **DeepL API Free** | 번역 품질 최상 | 2026년 중반부터 신규 가입 중단, 신규는 소진형 Developer 플랜 | 리뷰어가 재현할 수 없는 키 조달 경로 |
| **Google Cloud Translation** | 안정적, 문서 풍부 | 무료 50만 자/월 (Azure의 1/4) | 무료 한도가 Azure F0에 크게 못 미침 |
| **MyMemory (키 불필요)** | 가입 없이 즉시 사용, 폴백 단계를 실번역으로 승격 가능 | 품질 불안정, 익명 호출 한도 낮음 | 폴백이 `[demo]`보다 나쁜 번역을 낼 위험 — 마커 폴백이 오히려 정직하다 |
| **Symposia 자막도 API 번역** | 파이프라인 일원화 | 같은 강연이 재생마다 다른 품질로 나옴, 자막 분량만큼 무료 한도 소모 | 시연 **결정성**이 실번역 이득보다 크다 |
| **캐시 없음** | 코드 단순 | 반복 문장마다 API 왕복 + 한도 소모 | 정형 문구 반복이 많은 진료 대화에서 손해가 명확 |

## 결과 (Consequences)

**얻는 것**

- 키 없이 클론만으로 데모가 돌아가고, 키를 넣으면 같은 코드가 실번역으로 승격된다.
- API 장애·지연이 대화를 막지 않는다. 최악의 경우에도 `[demo]` 문자열이 즉시 나온다.
- 폴백했다는 사실이 결과 문자열(`[demo]` 마커)과 `TranslationResult.failure`에 모두 드러나
  무음 실패가 되지 않는다.
- 자막 데모는 매 재생 동일 — 시연 리허설이 그대로 본 시연이 된다.

**잃는 것 / 감수하는 것**

- **동작이 환경에 따라 갈린다.** 같은 입력이 키 유무에 따라 다른 결과를 낸다. 재현 문의가
  들어오면 "키를 넣었는지"부터 확인해야 한다.
- **테스트가 실번역을 검증하지 못한다.** Azure 경로는 mock 계약 검증까지이고, 실제 번역 품질
  확인은 수동 스모크로 남는다.
- 캐시가 프로세스 메모리에만 있어 서버 재시작 시 사라진다. 데모 규모에서는 문제되지 않지만
  실서비스라면 외부 캐시가 필요하다.
- Azure는 계정 + 카드 등록이 필요해, 리뷰어가 직접 실번역을 켜보려면 진입 장벽이 있다.
- 자막과 대화의 번역 경로가 갈라져 "번역"이라는 한 단어가 두 가지를 뜻하게 된다 —
  `translate.ts` 상단 주석과 테스트 가드로 경계를 못 박아 두었다.
