# 0006. 목 서버는 Render 무료 웹 서비스에, 웹 산출물 3종은 Vercel에 배포한다

- **상태**: Accepted
- **날짜**: 2026-09-01
- **관련**: [0002](./0002-live-demo-expo-react-native.md), [0003](./0003-sse-for-broadcast-ws-for-conversation.md), [중간 점검 §질문 B](../2026-09-01-checkpoint.md), [S07](../specs/S07-deployment.md)

## 맥락 (Context)

ADR-0002의 전제는 "리뷰어는 링크 클릭만으로 데모를 본다"인데, 아무것도 배포돼 있지
않았다. 배포 대상은 성격이 둘로 갈린다.

- **`apps/mock-server`** — SSE 브로드캐스트와 WebSocket 대화를 위해 **상시 프로세스**가
  필요하다. 세션 재생 타이머가 계속 돌아야 하고 연결이 분 단위로 유지돼야 하므로,
  정적 호스팅은 물론 요청 단위로 깨어나는 서버리스(함수)도 구조적으로 맞지 않는다.
- **product · live-demo 웹 빌드 · Storybook** — 전부 정적/Next 산출물이라 선택지가 넓다.

제약은 **비용 무료**이고, 운영 부담이 적은 단순한 서비스를 선호한다(사용자 확인, 9/1).
데모 서버라 가용성 요구는 낮다.

## 결정 (Decision)

- `apps/mock-server`는 **Render 무료 웹 서비스**에 배포한다.
- `apps/product`(Next.js) · `apps/live-demo`의 `expo export --platform web` 산출물 ·
  `packages/ui`의 Storybook 빌드는 **Vercel**에 배포한다.
- 배포와 동시에 mock-server의 CORS를 `*`에서 배포 도메인 화이트리스트로 좁힌다.

## 검토한 대안 (Alternatives)

목 서버(상시 프로세스) 후보만 비교한다. 웹 3종은 무료·간편의 차이가 크지 않아 Vercel로 통일했다.

| 대안 | 장점 | 단점 | 탈락 사유 |
|------|------|------|-----------|
| **Render 무료 (채택)** | WS·SSE 상시 프로세스 지원, **카드 등록 불필요**, 월 750 인스턴스 시간으로 서비스 1개 상시 가동, 설정 최소 | 15분 무트래픽 시 슬립 → 콜드스타트 수십 초 | — |
| Koyeb 무료 | 웨이크가 빠름 | 카드 검증 필요 | 무료인데 카드 등록을 요구해 "클론해서 바로" 원칙과 어긋남 |
| Cloud Run | 한도 넉넉, 확장성 | 유휴 CPU 스로틀로 **브로드캐스트 타이머가 지연될 수 있음**, 설정 복잡 | 세션 재생이 타이머 기반이라 스로틀이 데모 품질을 직접 훼손 |
| Fly.io | 상시 프로세스에 적합했던 선택지 | 무료 플랜 폐지 | 무료 조건 미충족 |
| Railway | 설정 간편 | 일회성 크레딧 소진형 | 크레딧 소진 후 데모 링크가 죽음 |

## 결과 (Consequences)

- (+) 카드 등록 없이 무료로 SSE·WS를 상시 노출한다. 리뷰어가 링크만으로 실시간 동작을 본다.
- (+) 웹 3종이 Vercel 한 곳에 모여 환경변수(`NEXT_PUBLIC_DEMO_URL`, `EXPO_PUBLIC_API_URL`)
  관리가 단순해진다.
- (−) **콜드스타트**: 15분 유휴 후 첫 접속이 수십 초 걸린다. 데모 특성상 수용하되, README에
  명시하고 필요하면 `/health` 핑을 주기적으로 걸어 완화한다.
- (−) 재기동 시 공유 브로드캐스트가 처음부터 재생된다. 학회 세션을 "중간부터 이어서"
  복원하지는 않는다 — 데모 범위로 허용한다.
- (−) live-demo 웹은 SPA라 `/session/:id`·`/room/:code` 경로에 rewrite 설정이 필요하고,
  WS는 `wss://`로 유도돼야 한다(`config.ts`의 WS_BASE 파생 로직 확인 대상).
